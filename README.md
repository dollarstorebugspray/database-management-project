# Grocery Store E-Commerce Database

INFSCI 2710 group project: a web-based grocery-store system backed by MySQL. The database models customers (home and business), products, categories, stores, regions, salespersons, orders, order items, and **inventory per store**.

## Project status

- **Database:** `database/schema.sql` creates the 11 tables; `database/sample-data.sql` inserts test records.
- **Backend:** Java 25 + Spring Boot 4 + Maven, with a working `GET /api/products` endpoint.
- **Frontend:**

## Set up the project on a Windows computer

### 1. Download the project

1. Open the group's GitHub repository.
2. Select **Code > Download ZIP**.
3. Extract the ZIP to a convenient location, e.g. `Documents\grocery-store-project`.
4. Confirm the extracted folder contains `database/` and `backend/pom.xml`.

If the ZIP extracts into a folder with an extra suffix (e.g. `grocery-store-project-main`), use that folder's actual name in the commands below.

### 2. Install required software

- [Java JDK 25](https://adoptium.net/temurin/releases/?version=25) (or another Java 25 JDK)
- [MySQL Community Server 8.4](https://dev.mysql.com/downloads/mysql/8.4.html)
- [MySQL Workbench](https://dev.mysql.com/downloads/workbench/) (recommended for running the scripts)

Check Java in **PowerShell**:

```powershell
java -version
javac -version
```

Both commands should report Java 25. Configure `JAVA_HOME` / `PATH` if necessary. Maven does **not** need to be installed separately: the backend includes `mvnw.cmd`.

### 3. Set up the local MySQL database

1. Start the local MySQL Server service.
2. Open MySQL Workbench and connect to `localhost:3306` using an administrator account (e.g. `root`).
3. Open and execute **`database/schema.sql` first**.
4. Open and execute **`database/sample-data.sql` second**.
5. Verify the tables and data:

```sql
USE grocery_store;
SHOW TABLES;
SELECT COUNT(*) AS product_count FROM Product;
SELECT * FROM Product;
```

The included sample data contains 20 products. **Do not run `sample-data.sql` repeatedly without resetting the tables**, because it uses fixed primary key IDs and a second run will cause duplicate-key errors.

If you need a fresh database, use MySQL Workbench to run `DROP DATABASE grocery_store;` **only if it is your disposable local project database and you are certain you want to erase all its data**, then run both SQL scripts again.

### 4. Create a local MySQL account for the backend

In MySQL Workbench, while signed in as an administrator, execute the following. Substitute your own secure password:

```sql
CREATE USER 'grocery_app'@'localhost' IDENTIFIED BY 'replace_with_secure_password';
GRANT SELECT, INSERT, UPDATE, DELETE ON grocery_store.* TO 'grocery_app'@'localhost';
```

This account is for local application data access. If it already exists, do not rerun `CREATE USER`; instead use its existing credentials or ask a teammate to confirm the intended setup. Each developer can use a different local password.

### 5. Configure the backend

Open `backend/src/main/resources/application.properties` and verify it contains the following values (retain other harmless Spring settings if present):

```properties
spring.application.name=backend
spring.datasource.url=jdbc:mysql://localhost:3306/grocery_store
spring.datasource.username=grocery_app
spring.datasource.password=${DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
server.port=8080
```

- `DB_PASSWORD` is an environment variable, **not a value to commit to GitHub**.
- `ddl-auto=validate` checks your Java mappings against the SQL-created tables; it does not create or replace them.
- If the local MySQL server uses another port, update `3306` accordingly.

### 6. Run Spring Boot

Open **PowerShell**, go to the backend directory, and enter:

```powershell
cd "$HOME\Documents\grocery-store-project\backend"
$env:DB_PASSWORD = "your_local_grocery_app_password"
.\mvnw.cmd spring-boot:run
```

Adjust the `cd` path to the location where you extracted the project. Keep this PowerShell window open while testing the API. The first run downloads Maven dependencies, so an internet connection is required.

If the console reports that the application has started and Tomcat is listening on port 8080, open:

**http://localhost:8080/api/products**

The endpoint should return a JSON array of 20 grocery products from MySQL, including product IDs, names, brands, prices, and category IDs. No frontend is required to test this endpoint.

### 7. Troubleshooting

| Symptom | Check |
| --- | --- |
| `java` or `javac` not recognized | JDK 25 installation, `JAVA_HOME`, and `PATH` |
| `Access denied for user 'grocery_app'` | Account exists, correct password, and `DB_PASSWORD` set in this PowerShell window |
| `Communications link failure` | MySQL service is running, URL/host/port are correct |
| Schema validation failure / missing table | Execute `schema.sql`; confirm names in the `Product` entity match SQL columns |
| `[]` at `/api/products` | Query `Product` in MySQL and load `sample-data.sql` if empty |
| Port 8080 already in use | Stop the other application or change `server.port` |
| PowerShell cannot find `mvnw.cmd` | Make sure your current directory contains `backend/pom.xml` and `backend/mvnw.cmd` |

## Database tables

`Customer`, `HomeCustomer`, `BusinessCustomer`, `Region`, `Store`, `Salesperson`, `Category`, `Product`, `Inventory`, `Orders`, `OrderItem`.

`Inventory` is keyed by `(store_id, product_id)` so the same product can have different stock levels at different stores. `OrderItem` is keyed by `(order_id, product_id)` and records the quantity and historical sale price per item.

## Collaborating through GitHub (no Git CLI required)

- **To get updates:** use **Code > Download ZIP**, extract a fresh copy, and transfer any unuploaded local work carefully.
- **To upload changes:** go to the intended folder on GitHub, choose **Add file > Upload files**, drag in the new/updated project files and commit them. Verify that files appear in the intended paths.
- **Avoid overwriting teammates' changes:** coordinate who is editing each file before uploading. The GitHub website alone does not automatically merge separate local ZIP copies.
- **Never upload** database passwords, `.env` files, `backend/target/`, `.idea/`, `.vscode/` personal settings, or generated compiled binaries. Preserve the Maven wrapper files, including `.mvn/wrapper/`, `mvnw`, and `mvnw.cmd`.

A `.gitignore` is useful, but **manually check browser uploads too**; do not assume `.gitignore` prevents a selected file from being uploaded on GitHub's website.
